**优先级**: P1

**项目目录**: D:/game-projects/steam-horror-sim/

## 前置条件
- M1 已完成（Task #37）：Canvas渲染+30x25地图+WASD移动+E交互+光照+6阶段状态机
- M2 已完成（Task #38）：商品管理+顾客AI+收银+定价+经济循环，v0.2.0

## M3 交付范围

### 1. 日循环管理（DayCycle.ts）
- 完整一天循环：06:00 新一天 → 白天经营 → 22:00 准备打烊 → 23:00 深夜经营 → 02:00 危险时段 → 05:00 黎明 → 06:00 新一天
- 游戏内时间流速：1现实秒 = X游戏分钟（可调，推荐白天1:10，夜晚1:5）
- 阶段切换触发器：每个阶段开始时广播事件
- 天数计数器，每日重置相关状态

### 2. 光照系统升级
- 白天/夜晚光照自动切换（06:00 日出渐亮，18:00 日落渐暗）
- 白天：均匀暖光覆盖全店
- 夜晚：有限光源（收银台灯、货架灯、门口灯），暗角区域
- 光照强度随时间渐变（smooth transition）
- 利用已有 Lighting.ts 扩展

### 3. 店铺升级系统（UpgradeManager.ts）
- 6种升级（参考GDD 5.4节）：
  1. 更亮的灯（¥500）— 照明+50%
  2. 仓库货架（¥800）— 库存+50%
  3. 收银机升级（¥1000）— 交易速度+30%
  4. 监控摄像头（¥2000）— 预留恐怖系统接口
  5. 防盗门（¥3000）— 预留恐怖系统接口
  6. 紧急按钮（¥5000）— 预留恐怖系统接口
- 升级购买界面（Canvas绘制）
- 升级效果应用到对应系统（库存上限、交易速度等）
- 恐怖关联先做占位接口，M4-M5 再实现

### 4. 日结算系统（DaySummary.ts）
- 每日05:00结算：
  - 今日收入 vs 支出
  - 净利润
  - 顾客数统计
  - 库存状态
- 结算界面（Canvas绘制，简单列表）
- 数据写入 EconomySystem 的历史记录

### 5. 存档系统（SaveManager.ts）
- 自动存档：每个日结算后自动存档
- 存档内容：天数、资金、库存、升级状态、经济数据
- localStorage 存储（JSON序列化）
- 读档恢复所有系统状态

## 技术要求
- TypeScript 严格模式，零编译错误
- Canvas 渲染（与 M1/M2 一致）
- 保留 M1+M2 所有功能，M3 是增量开发
- GameState 需要新增 day、timePhase 等字段
- 利用事件总线或回调在各系统间通信

## 验收标准
1. 完整一天循环可体验：白天经营→打烊→深夜→黎明→新一天
2. 光照白天/夜晚有明显视觉差异
3. 至少 6 种店铺升级可购买且效果生效
4. 日结算正确计算收支
5. 存档/读档功能正常
6. TypeScript 零编译错误，Vite 构建成功

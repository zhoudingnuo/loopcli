## 2. Bug 列表（按严重级别）

### P0 - 严重（影响核心玩法）

**BUG-1: DailySystem clear_obstacle 事件双倍计数**
- 文件: `DailySystem.js:107-122`
- 问题: `reportEvent` 方法先匹配 `task.type === eventType` 增加 progress，然后又单独匹配 `task.type === 'clear_obstacle' && eventType === 'clear_obstacle'` 再次增加。导致消除1个障碍计数为2。
- 修复: 将第二个 `if` 改为 `else if`，或将通用的 progress 逻辑排除 clear_obstacle 类型。

**BUG-2: Board.shuffle 未处理 null 格子会崩溃**
- 文件: `Board.js:262-263`
- 问题: `shuffle()` 假设所有格子都有 tile 对象，但巧克力障碍物会清空格子（grid[r][c] = null）。访问 null.color 会抛 TypeError。
- 修复: shuffle 前过滤掉 null 格子，或仅收集非 null 的颜色。

**BUG-3: ScoreSystem.useMove 允许第0步时继续操作**
- 文件: `ScoreSystem.js:70-73`
- 问题: `return this.getRemainingMoves() >= 0` — 当剩余步数为0时仍返回true，允许在最后一步之后再操作一次。应为 `> 0`（步数用尽前允许操作）或 `>= 0` 但在 addMove 之后检查。
- 实际影响: 最后一步操作后 remaining=-1，但 checkState 在之后才触发，可能导致多走一步。

**BUG-4: applyGravity 新方块 offsetY 单位不一致**
- 文件: `Board.js:219` + `Game.js:361`
- 问题: Board.applyGravity 填充新 tile 时 `tile.offsetY = -(writeRow - r + 1)` 用的是格子数单位，但 Game._processChain 中重力动画用像素偏移 `fromRow * tileSize`。新方块的掉落动画位置不正确。
- 修复: Board.js:219 改为 `tile.offsetY = -(writeRow - r + 1) * tileSize` 或在 Game.js 中统一处理。

### P1 - 高（影响功能完整性）

**BUG-5: 特殊方块创建后不会自动触发清除效果**
- 文件: `Game.js:303-308` + `Game.js:336-338`
- 问题: 匹配生成特殊方块（条纹/炸弹）后，`_triggerSpecialEffects` 只播放粒子/音效，不执行实际清除逻辑。特殊方块留在棋盘上只能通过手动交换才能触发。这与标准三消行为不符（通常匹配生成后立即触发）。
- 设计决策: 如果是刻意设计（需要玩家主动触发），则无需修复。但用户体验可能困惑。

**BUG-6: Characters auto_obstacle 技能未从 obstacles 数组移除**
- 文件: `Characters.js:48-49`
- 问题: 直接设置 `t.hp = 0` 但不移出数组。虽然 `isDestroyed()` 返回 true，但数组持续增长，`find`/`filter` 操作变慢。
- 修复: 调用 `obstacleMgr.onTilesMatched` 或在 Game 层统一清理。

**BUG-7: InputHandler 和 canvas click handler 双重处理**
- 文件: `index.html:77-99` + `InputHandler.js:27-49`
- 问题: InputHandler 绑定了 mousedown/mouseup 事件处理棋盘操作，但 index.html 的 canvas click handler 也可能触发相同事件。可能导致一次操作被处理两次。
- 修复: 统一事件处理入口，去掉重复绑定。

**BUG-8: _handleTap 功能不完整**
- 文件: `Game.js:152-159`
- 问题: 点击处理只检查了彩虹方块然后 return，没有实现「选择→再点击相邻方块交换」的桌面端交互。桌面用户必须使用滑动操作，体验不佳。

### P2 - 中（体验问题）

**BUG-9: levels.js 注释过时**
- 文件: `levels.js:1`
- 问题: 注释写 "20 level definitions for Phase 2"，实际有50关。
- 修复: 更新注释。

**BUG-10: 关卡JSON文件未被使用**
- 文件: `levels/level_01.json` ~ `level_20.json`
- 问题: 游戏从 levels.js 的 LEVELS 数组加载关卡，levels/ 目录下的20个JSON文件完全未被引用，是死代码。
- 修复: 删除或更新加载逻辑使用JSON文件。

**BUG-11: _roundRect 函数重复7次**
- 文件: Renderer, MapScreen, ShopUI, Navigation, DailySystem, SocialSystem, AdManager
- 问题: 相同的圆角矩形绘制函数复制粘贴在7个文件中。
- 优化: 提取到公共工具模块。

**BUG-12: localStorage 保存过于频繁**
- 文件: DataManager.save() 被多处频繁调用
- 问题: 每次消除障碍、每次金币变动、每次分析事件、每次每日任务进度更新都立即 save。在低端设备上可能导致卡顿。
- 优化: 使用 debounce（如每2秒最多save一次）。

**BUG-13: 粒子系统无对象池**
- 文件: `Animation.js:108-155`
- 问题: 每次发射粒子都 new Particle()，依赖GC回收。大量连锁消除时可能造成微卡顿。
- 优化: 实现粒子对象池。

**BUG-14: 无音效开关UI**
- 文件: AudioManager.js:131-134
- 问题: `toggle()` 方法存在但UI中没有音效开关按钮。用户无法关闭音效。

**BUG-15: Boss血量过高导致关卡难度失衡**
- 文件: `levels.js` (Level 35, 50)
- 问题: Level 35 Boss 200HP（18步）、Level 50 Boss 300HP（25步）。每次相邻消除只造成5-10点伤害，理论最大伤害约180-250，实际很难在限定步数内击杀。
- 修复: 降低Boss HP或提高伤害系数。

## 修复清单

### 1. CORS 白名单模式 (P1 - Medium)
**问题**: `_cors_headers` 使用 `Access-Control-Allow-Origin: *`，允许任何来源跨域请求。
**修复**:
- 新增 `CORS_ORIGINS` 模块级变量，从环境变量 `CORS_ORIGINS` 读取白名单（逗号分隔）
- `_cors_headers` 方法改为：若配置了白名单，检查请求 `Origin` 头是否在白名单内，匹配则回显该 Origin + `Vary: Origin`；不匹配则不返回 CORS 头
- 未配置 `CORS_ORIGINS` 时保留 `*` 作为开发回退
- `do_OPTIONS` (preflight) 同样使用新逻辑

**代码位置**: server.py:28, 232-241

### 2. 写操作并发限制 (P1 - Medium)
**问题**: 所有 POST 端点无并发限制，可被 DoS 攻击耗尽线程资源。
**修复**:
- 新增 `_write_semaphore = threading.Semaphore(10)`，限制最多 10 个并发写操作
- `do_POST` 重构为先获取信号量（5 秒超时），超时返回 503
- 原有 POST 逻辑移入 `_do_POST_impl()`，在 `try/finally` 中确保信号量释放

**代码位置**: server.py:30, 342-352

### 3. SSE 连接超时 + 最大连接数 (P1 - Medium)
**问题**: `/api/logs/stream` SSE 端点无限运行，无连接数限制，可导致资源耗尽。
**修复**:
- 新增 `_sse_connections` 计数器 + `_sse_lock` 线程锁
- `SSE_MAX_CONNECTIONS = 10`，超限返回 503
- `SSE_TIMEOUT_SECONDS = 300`（5 分钟），超时发送 `timeout` 事件后正常关闭
- `finally` 块确保连接计数正确递减

**代码位置**: server.py:32-35, 250-303

## 逐项验证详情

### 1. CORS 默认值：http://localhost:3000 替代 *

**修复位置**：`server.py:32-36`

```python
_raw_cors = os.environ.get("CORS_ORIGINS", "").strip()
if _raw_cors:
    CORS_ORIGINS = [o.strip() for o in _raw_cors.split(",") if o.strip()]
else:
    CORS_ORIGINS = ["http://localhost:3000"]
```

**CORS 响应头逻辑**：`server.py:281-290`
```python
def _cors_headers(self):
    origin = self.headers.get("Origin", "")
    if CORS_ORIGINS:
        if origin in CORS_ORIGINS:
            self.send_header("Access-Control-Allow-Origin", origin)
            self.send_header("Vary", "Origin")
    else:
        self.send_header("Access-Control-Allow-Origin", "*")
```

**验证结果**：
- 默认 `CORS_ORIGINS = ["http://localhost:3000"]`，不再使用 `*`
- Origin 校验为精确匹配（白名单模式），正确实现同源策略
- `Vary: Origin` 头正确设置，防止 CDN 缓存混淆攻击
- OPTIONS 预检请求也经过 `_cors_headers()`（line 446-448），一致

**边界情况（信息级）**：若 `CORS_ORIGINS` 环境变量设为纯逗号/空格（如 `CORS_ORIGINS=,,`），列表推导产生空列表 `[]`，会回退到 `*`。这是管理员配置错误场景，不影响默认安全性。

**结论**：VERIFIED

### 2. write_json 并发锁：_json_lock = threading.Lock()

**修复位置**：`server.py:28`（锁定义）、`server.py:55-58`（使用）

```python
_json_lock = threading.Lock()

def write_json(path: Path, data):
    with _json_lock:
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
```

**验证结果**：
- `threading.Lock()` 确保同一时刻只有一个线程执行 JSON 写入
- `with` 语句保证锁在异常时自动释放
- 所有 `write_json` 调用点（task 创建、state 更新、loop 状态、agent enable/disable）均通过同一个锁串行化
- `read_json`（line 46-52）未加锁，这是可接受的：
  - JSON 文件很小（通常 <10KB），`write_text()` 在 Windows 上接近原子操作
  - 最坏情况是读到上一版本数据，不会导致数据损坏

**结论**：VERIFIED
